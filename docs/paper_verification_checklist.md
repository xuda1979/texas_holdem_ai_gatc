# Paper → Code Verification Checklist

This checklist helps ensure the algorithms described in `paper.tex` are:
1) mathematically correct, 2) implemented in this repository, and 3) make a
reasonable claim of innovation (efficiency or performance).

## Mathematical correctness
- [ ] Definitions: Information set, strategy, regret, average strategy are defined precisely.
- [ ] CFR update rule: cumulative regret uses counterfactual values; only positive regrets are used for strategy updates in CFR+ (if applicable).
- [ ] Strategy normalization: per-information set action probabilities sum to 1.
- [ ] Convergence statements are properly scoped (e.g., average strategy convergence, exploitability trends).
- [ ] Assumptions and approximations (abstractions, pruning, sampling) are clearly stated with known effects.
- [ ] References to canonical sources (e.g., Kuhn (1950/1951), CFR/Deep CFR papers) are cited for theorems/known results.

## Implementation presence
- [ ] For each algorithm named in the paper (e.g., CFR, CFR+, Deep CFR, Single-Network CFR), there is a concrete module/file.
- [ ] The code includes unit tests validating invariants (normalization, absence of NaNs/Infs).
- [ ] A toy-game sanity harness (Kuhn Poker) demonstrates expected qualitative behavior (e.g., monotone betting frequencies J < Q < K).

## Innovation claims
- [ ] Efficiency: time/space complexity reductions are measured (profiling results or ablation).
- [ ] Performance: exploitability or winrate gains shown with consistent evaluation settings.
- [ ] Ablations isolate the contribution of the new component (e.g., pruning, transformer featurization, curriculum).
- [ ] All baselines are well-implemented or referenced, with matching hyperparameters when appropriate.

## Artifacts to keep up-to-date
- [ ] `paper_alignment_report.json` (generated by `tools/tex_alignment_checker.py`)
- [ ] CI: run unit tests and sanity harness on each PR
- [ ] Metrics logs from training runs (`runs/<exp>/metrics.jsonl`)

> Tip: Use the tiny monitoring subsystem in `poker_ai.monitoring` to catch NaNs/Infs and log basic metrics during early experiments.
